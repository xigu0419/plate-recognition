# 智能车牌识别系统 v3.0

基于 **Python 3.9 + OpenCV + PaddleOCR** 的图片车牌识别程序，带图形界面。

---

## 一、两个版本

| 版本 | 用途 | 位置 |
|------|------|------|
| **源码版** | 自己用 / 交作业 / 改代码 | `plate_recognition.py` |
| **分享版** | 发给同学，双击即用，无需装任何环境 | `dist\车牌识别工具_分享版\` |

## 二、源码版怎么用

### 1. 环境（已经配好了，直接用即可）
Anaconda 里的 `plate` 环境：
```
C:\Users\user\.conda\envs\plate\python.exe
```
环境内已安装：Python 3.9、OpenCV 4.6、PaddleOCR 2.7、PaddlePaddle 2.6、Pillow、NumPy。

### 2. 三种启动方式（任选一种）

**方式 A（最推荐）：双击 `启动程序.bat`**
双击即可，它会自动用对的 Python 跑。

**方式 B：直接双击 `plate_recognition.py`**
也行 —— 程序启动时会自检，发现当前 Python（系统的 3.14）没有 PaddleOCR，
就**自动切换到 `plate` 环境重新启动**，你看到的还是正常界面。
（首次可能要多等 2~3 秒。）

**方式 C：命令行**

打开 CMD / PowerShell，输入：
```bash
cd /d D:\plate_recognition
C:\Users\user\.conda\envs\plate\python.exe plate_recognition.py
```

> 三种方式打开的都是同一个图形界面：点「选择图片」→ 选车牌照片 → 点「开始识别」。

### 3. 只想快速识别一张图（不开界面）

把图片拖到 `识别车牌.bat` 上，或者：
```bash
cd /d D:\plate_recognition
C:\Users\user\.conda\envs\plate\python.exe plate_recognition.py 图片.jpg
```
输出示例：
```
==============================================
  智能车牌识别系统 v3.0
==============================================
[图片] sample_images\OIP-C.jpg
[识别到 1 个车牌]
  1) 京A12345      置信度 95.4%  [合法]
[标注图] sample_images\OIP-C_result.jpg
```
识别结果图会存成 `图片_result.jpg`（绿框 = 合法车牌，橙框 = 存疑）。

> 若已激活 plate 环境（`conda activate plate`），直接 `python plate_recognition.py` 即可。

### ⚠️ 关于「OCR 引擎不可用」

如果直接用系统的 Python（3.14）运行，会提示 `OCR 引擎不可用`，因为：

| Python | 有 PaddleOCR 吗 |
|--------|----------------|
| 系统自带的 3.14 | ❌ 没有（3.14 装不了 PaddleOCR） |
| conda 的 `plate` 环境（3.9） | ✅ 有 |

**程序已经自动处理了这个问题**：即使用错误的 Python 启动，它也会自动切换到 `plate` 环境重新运行，你正常用就行。

如果因为某些原因没切换成功，就改用双击 `启动程序.bat`，或显式用上面的完整路径运行。

## 四、识别原理

```
读入图片
   │
   ▼
① 车牌定位 —— PaddleOCR 文字检测(DBNet) + OpenCV 颜色分割，两路互补
   主路：用 PaddleOCR 自带的文字检测模型找文字行，再按「宽高比≈3.14
        （单层牌）、字符框能连成一行」筛出车牌候选。
        这个模型见过海量真实场景文字，对色偏、暗光、模糊都很稳。
   辅路：OpenCV 在 HSV 空间分割 蓝/绿/黄 车牌底色 + 形态学闭运算
        + 轮廓筛选，车牌特写时仍然有用。
   │
   ▼
② 透视矫正 —— 用候选框的四个角点做透视变换(deskew)
   把倾斜/斜拍的车牌掰成水平矩形。
   检测框往往比车牌外框略紧、会切掉边上的字，所以认不出合法车牌时
   会向外留边再认一次。
   │
   ▼
③ 字符识别 —— 直接调用 PaddleOCR 的识别模型（跳过检测模型）
   关键：车牌区域本来就是单行文本。如果再走一遍检测，检测模型会把这个
   窄长条重新切分，把首位的省份汉字切成单独的框然后丢掉，于是
   「皖AX188Y」变成「X188」、「皖AY5E19」变成「皖AY5E」。
   直接喂给识别模型整条一起解码，这类错误全部消失。
   三个尺度(原图/2x/3x/4x)一起送去识别 → 投票
   │
   ▼
④ 结果校验 —— 车牌格式打分
   首位必须是省份简称(京津冀鲁粤…)，第二位必须是字母，长度 7~8 位。
   像「鱼Q67858」这种结果，因为「鱼」不是省份字，会被自动淘汰。
   │
   ▼
输出车牌号 + 置信度 + 标注图
```

**为什么置信度高不代表结果对？**
实测中「放大3倍」得到了 99.65% 的结果却是错的（漏了"鲁"字）。
所以程序不只看置信度，而是用**多尺度投票 + 车牌格式校验**综合判断。

## 五、用数据集做过什么（准确率是怎么来的）

为了让"识别准不准"有客观依据，程序用 **CCPD 车牌数据集**（6000 张真实街景
车辆照片）做了完整评测，脚本都在本目录，可复现：

| 脚本 | 作用 |
|------|------|
| `prepare_ccpd.py` | 解析数据集、下载图片、生成标注 |
| `check_dataset.py` | 校验标注解析是否正确 |
| `evaluate_ccpd.py` | 批量评测（支持两种模式，见下） |
| `summary_report.py` | 汇总所有评测结果，生成实验报告 |

`evaluate_ccpd.py` 有两种模式，用来区分瓶颈在"定位"还是在"识别"：

| 模式 | 含义 |
|------|------|
| `--mode gt-crop` | 用数据集给的真值角点精准裁剪，**只测识别能力** |
| `--mode full` | 完全走程序自己的定位+识别，**测端到端真实效果** |

### 实测结果（CCPD test 500 张）

| 阶段 | 整牌正确率 | 定位命中率 |
|------|-----------|-----------|
| ① 优化前（颜色定位 + 检测+识别流程） | 94.1% | 49.6% |
| ② 优化前（用真值角点裁剪，只测识别能力） | 95.4% | 100% |
| ③ 修复识别流程（直接调用识别模型，只测识别能力） | **100.0%** | 100% |
| ④ 改用 PaddleOCR 文字检测做定位 | 98.4% | 98.6% |
| ⑤ 再修掉倾斜车牌被误滤 + 放宽留边条件 | **99.0%** | **100%** |

最终端到端 **99.0%（495/500）**，字符正确率 **99.8%**。
剩下 5 张错的全是模糊样本上的字符级混淆（Q/0、Y/0、1/I 之类）
和 1 张省份偏置，属于识别模型本身的能力边界。

完整的分析过程和失败样例见 `实验报告_数据集评测.md`。

### 定位方式的对比（同一批 500 张测试图）

| 定位方式 | IoU≥0.5 命中率 | 中位 IoU |
|---------|---------------|---------|
| OpenCV HSV 颜色阈值 | 20.7% | — |
| PaddleOCR 文字检测 | **100%** | 0.91 |

这就是为什么定位主力换成了文字检测模型 —— 颜色阈值在真实照片里
（色偏、逆光、夜间、车牌小）失败率太高。颜色分割代码仍然保留，
作为车牌特写等情况下的补充。

### 四个踩过的坑（都是数据集测出来的）

1. **识别被自己的检测流程切坏**：车牌条是单行文本，再走一遍 PaddleOCR 的
   「检测+识别」会被重新切分，把首位省份汉字丢掉（`皖AX188Y` → `X188`）。
   改成**直接调用识别模型**后，`gt-crop` 模式从 95.4% 变成 **100%**，
   单张耗时也从 1625 ms 降到 133 ms。

2. **倾斜车牌被自己的过滤条件误杀**：判断「像不像车牌」时用了**轴对齐外接框**
   算宽高比，而车牌旋转 25~32° 后外接框会变成近似正方形（宽高比只有 1.09~1.30），
   于是正确的检测框被当成「形状不对」丢掉。改成按**四边形真实边长**算就好了。

3. **两路候选分数量纲不同**：颜色候选按面积占比算分能到 3.0，文字候选只有 2.3，
   只按分数排会把文字候选整个挤出前几名。改成**先按来源分主次**再看得分。

4. **一张图只有一块车牌却显示两三块**：去重原来只看「候选中心点距离 < 40 像素」，
   而同一块车牌会同时生成「整块车牌框」和「把字符合并成行的框」，两者大小不同、
   中心能错开 40 像素以上，于是同一块牌被识别并显示多次。实测 500 张测试图里
   有 **7.3%** 出现这种情况（最严重的显示 3 块，号码还都一样）。

   修法是两层：
   - **按框重叠去重**（IoU ≥ 0.3 就算同一块），不再只看中心点距离；
   - **只显示通过车牌格式校验的结果**，否则车标、店铺招牌会被当成车牌报出来
     （实测会多报 `AOKANG`、`沿街旺铺`、`SANTAN`、`百姓`、`02025` 这类噪声）。

   修完重复率 7.3% → **0%**，准确率没有回退。

### 数据集的局限（要如实说明）

CCPD 采集自安徽合肥，**96% 的车牌是「皖」开头**。所以模型有省份偏置，
实测 12 张「鲁」牌里有 1 张被读成「皖」。这是数据集本身的局限，
不是程序缺陷。

## 七、重新打包

```bash
cd /d D:\plate_recognition
C:\Users\user\.conda\envs\plate\python.exe build_share.py
```

打包踩过的坑都写在 `build_share.py` 开头的注释里了，主要有 5 个：

1. **`_ctypes` 加载失败** → conda 的 `_ctypes.pyd` 依赖 `Library\bin\ffi.dll`，需把该目录所有 DLL 一起打包
2. **`imghdr` / `imgaug` / `lmdb` 缺失** → paddleocr 内部用 `import tools.xxx` 这类顶层导入，PyInstaller 分析不到，要用 `--collect-all` / `--hidden-import` 补齐
3. **`PackageNotFoundError: imageio`** → 缺 dist-info 元数据，用 `--copy-metadata` + 程序内兜底补丁
4. **中文路径下模型打不开** → Paddle C++ 接口不支持非 ASCII 路径，程序启动时自动复制模型到临时 ASCII 目录
5. **体积莫名涨到 1028 MB** → 做数据集实验时往 conda 环境装过 PyTorch，被 PyInstaller 一起收进来了（光 torch 就 311 MB）。用 `--exclude-module torch` 等排除后回到 704 MB。**程序运行时不需要 torch。**
6. **写 `.bat` 时 `UnicodeEncodeError`** → 启动器里有中文文件名，必须用 UTF-8 写，不能用 ascii

打包完成后建议**实测一次 exe** 再发人：
```bash
"C:\...\dist\车牌识别工具_分享版\车牌识别工具.exe" 某张车牌图.jpg
```
跑完会在同目录生成 `某张车牌图_result.jpg`，能看到绿框和识别结果就说明没问题。

## 八、常见问题

**Q：双击 exe 没反应？**
首次启动需解压运行库，等 10~20 秒。若仍无反应，看同目录的 `错误日志.txt`。

**Q：识别不出来？**
换车牌正面、清晰、光线好的照片。车牌在图中越大越准。

**Q：能识别什么车牌？**
蓝牌（普通燃油车）、绿牌（新能源）、黄牌。第一位省份汉字 + 字母 + 数字的 7~8 位组合。

**Q：识别记录能保存吗？**
界面上会显示历史记录，结果图保存在原图同目录（`原文件名_result.jpg`）。
